# Unicode 双向文本方向标记

> 补充说明：RTL 界面里，电话号码、用户名、英文片段等如何用不可见 Unicode 控制字符纠正显示顺序。  
> 设计背景见 [Apple RTL 设计与开发指南](./Apple-RTL设计与开发指南.md) 第四节。

这些字符**看不见**，只参与 Unicode 双向算法（Bidi），不改变字面内容。

---

## 一句话总览

| 写法 | 本质 | 有没有「管多长」 |
|------|------|------------------|
| `\u{200E}` / `\u{200F}` | **钉子**（Mark） | **没有**，只影响附近 |
| `\u{202A}`…`\u{202C}` | **嵌入**（Embedding） | **有**，开到闭 |
| `\u{2066}`…`\u{2069}` | **隔离**（Isolate） | **有**，开到闭，内外互不干扰（更推荐） |

源码里三种都像「中间夹一段文字」，**只有后两种才有真正的作用范围**。

---

## 常用字符表

| Swift 写法 | Unicode | 名称 | 作用 |
|------------|---------|------|------|
| `\u{202A}` | U+202A | LRE Left-to-Right Embedding | 开始：后续嵌入为 LTR |
| `\u{202B}` | U+202B | RLE Right-to-Left Embedding | 开始：后续嵌入为 RTL |
| `\u{202C}` | U+202C | PDF Pop Directional Formatting | 结束 LRE / RLE |
| `\u{200E}` | U+200E | LRM Left-to-Right Mark | 看不见的 LTR 字符（钉子） |
| `\u{200F}` | U+200F | RLM Right-to-Left Mark | 看不见的 RTL 字符（钉子） |
| `\u{2066}` | U+2066 | LRI Left-to-Right Isolate | 开始：LTR 隔离舱 |
| `\u{2067}` | U+2067 | RLI Right-to-Left Isolate | 开始：RTL 隔离舱 |
| `\u{2069}` | U+2069 | PDI Pop Directional Isolate | 结束 LRI / RLI |

## `\u{202A}` 包电话号码是什么意思？

```swift
let localized = "\u{202A}\(phoneNumber)\u{202C}"
```

在 RTL 句子里，界面从右往左排，但**电话号码全球习惯 LTR**（如 `408-555-1212`）。不加标记，号码可能被周围 RTL 文本带乱。

```
RTL 阿拉伯语 … [LRE] 408-555-1212 [PDF] … 继续 RTL
                  └──── 整段强制 LTR ────┘
```

类比：用括号注明「这段请从左往右读」——`202A` 开、`202C` 关。

---

## `\u{202A}` 和 `\u{200E}` 的区别

**`202A` 是「包一段」；`200E` 是「插一个点」。**

| | `\u{202A}`（LRE） | `\u{200E}`（LRM） |
|---|---|---|
| 作用 | **强制一整段**按 LTR 排 | 在这个位置插入一个**看不见的 LTR 字符** |
| 要不要配对 | 必须用 `\u{202C}` 结束 | **不需要**配对 |
| 类比 | 括号：这段请从左往右读 | 钉子：钉在某一个位置 |

```swift
// 包一段（有范围）
"\u{202A}408-555-1212\u{202C}"

// 钉一个点（无范围）
"\u{200E}\(userName) 欢迎回来"
```

Apple 文档：变量在**句首**且方向未知时，在变量前插 LRM（LTR 本地化）或 RLM（RTL 语言），避免整句被变量带偏。

## `protectLTRIsolate()` 为什么还有 `2066`…`2069`？

```swift
func protectLTRIsolate() -> String {
    return "\u{2066}\(self)\u{2069}"
}

func protectLTR() -> String {
    let lrm = "\u{200E}"
    return "\(lrm)\(self)\(lrm)"
}
```

`200E` **没有作用范围**，不知道字符串有多长。头尾各加一颗是**经验做法**，不是 Unicode 规定的「从第一个管到第二个」。

`2066`…`2069` 才是现代的「包一段」：Unicode 6.3 的 **Isolate（隔离）**。

| | `protectLTR()` | `protectLTRIsolate()` |
|---|---|---|
| 标记 | 头尾 `200E` | `2066` 开、`2069` 关 |
| 范围 | 无 | 中间整段 |
| 和外面 | 仍互相拉扯 | **隔离**，更干净 |

类比：

| 写法 | 像什么 |
|------|--------|
| `200E` 头尾 | 门口各放一块路障 |
| `202A`…`202C` | 围栏（里面仍可能影响外面） |
| `2066`…`2069` | **隔离舱**（内外互不干扰） |

包用户名、电话、产品名等独立一块 LTR 内容，**优先 Isolate**。

## 头尾都加 `200E`，能不能只加开头？

**一般不要改成只加开头。** 两颗钉子职责不同：

```swift
"\(lrm)\(self)\(lrm)"
//  ↑         ↑
//  管开头     管结尾
```

| 位置 | 解决什么 |
|------|----------|
| 前面的 LRM | 防止 `self` 第一个字符把整句方向带偏 |
| 后面的 LRM | 防止**结尾的标点、括号**被 RTL 吸到另一侧 |

`! ? . )` 是**中性字符**，自己没有方向，跟着旁边更强的方向走。RTL 段落里 `"Hello!"` 可能显示成 `!Hello`。结尾那颗 LRM 告诉算法：这段 LTR 在这里结束，标点跟 LTR 走。

只加开头：句首稳了，**句尾标点仍可能乱**。

例外：Apple 那种「只在句首钉住整句方向」——只在变量前插一颗即可，那不是在保护 `self` 这一整段。

---

## 头尾 `200E` 和 `202A`…`202C` 是不是一回事？

**不是。** 源码都像「中间包一段」，算法完全不同。

| | `200E` 头尾 | `202A`…`202C` |
|---|---|---|
| 有没有作用范围 | **没有** | **有**（开到闭） |
| 改不改嵌入层级 | 不改 | **改**（这段升为 LTR 嵌入） |
| 中间是阿语 | 仍是强 RTL，和外面连成一片 | 整块按嵌入规则排 |
| 和外面隔离 | 否 | 不完全（不如 Isolate） |

头尾 `200E` 对 Unicode 来说只是：

```
[LTR 钉子] + 原文每一个字符 + [LTR 钉子]
```

中间字符**没有被声明成「一段 LTR」**。纯英文 `"Hello!"` 时两者往往看起来差不多，所以容易误以为没区别。混排、阿语、括号时差别才明显。

## 三种写法对照

```swift
// 1) 钉子：无范围，头尾各一颗（技巧，不是作用域）
"\u{200E}\(self)\u{200E}"

// 2) 嵌入：有范围（Apple 旧文档电话号码示例）
"\u{202A}\(self)\u{202C}"

// 3) 隔离：有范围，内外隔离（推荐包独立片段）
"\u{2066}\(self)\u{2069}"
```

| 需求 | 用哪个 |
|------|--------|
| 电话号码、必须整段 LTR | `2066`…`2069`（或旧写法 `202A`…`202C`） |
| 句首变量怕带偏整句 | 变量前一颗 `200E` / `200F` |
| 保护一段可能含标点的字符串，暂用 LRM | 头尾都加 `200E`，不要只加开头 |
| 包一块独立内容（用户名、标题、产品名） | **Isolate `2066`…`2069`** |

---

## 记忆口诀

> **Mark（`200E`）是钉子，没有长度。**  
> **Embedding（`202A`…`202C`）是括号，有开闭。**  
> **Isolate（`2066`…`2069`）是隔离舱，有开闭且内外隔开。**
