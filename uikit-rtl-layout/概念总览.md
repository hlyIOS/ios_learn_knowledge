# 概念总览：所有概念是什么关系？

> 快速入门 · 一句话搞懂 UIKit RTL 布局相关概念

---

## 一句话版

**系统先定「大环境」，你给控件贴「身份标签」，系统再算出「实际怎么排」。**

---

## 三层流水线

```
① 环境层          ② 语义层              ③ 结果层
─────────        ──────────            ──────────
系统语言    →    semanticContent    →   layoutDirection
App 设置         Attribute              （最终布局方向）
Trait Collection
     ↓
基准布局方向
```

---

## 每个概念扮演什么角色？

| 概念 | 角色 | 一句话 |
|------|------|--------|
| **系统语言 / App 设置** | 源头 | 决定 App 默认 LTR 还是 RTL |
| **UITraitCollection** | 搬运工 | 把环境信息（含 layoutDirection）传给每一层 View/VC |
| **基准布局方向** | 大背景 | 还没看具体控件之前，界面默认从左还是从右 |
| **UISemanticContentAttribute** | 身份标签 | 这个控件是什么、该不该随语言翻转 |
| **UIUserInterfaceLayoutDirection** | 最终结果 | 这个控件实际该怎么排 |

---

## 怎么算出来的？

```
基准布局方向（来自 Trait / 系统语言）
        +
semanticContentAttribute（你设置的标签）
        ↓
effectiveUserInterfaceLayoutDirection（最终结果）
```

| 控件标签 | 在 RTL 环境下 |
|----------|--------------|
| `.unspecified`（普通 UI） | 跟随 → RTL |
| `.playback`（播放键） | 不翻转 → LTR |
| `.forceLeftToRight` | 强制 → LTR |

---

## 记忆口诀

> **Trait 传环境，Semantic 贴标签，Direction 是结果。**

---

## 开发者只需记两件事

1. **配置控件** → 设 `semanticContentAttribute`
2. **布局/绘制** → 读 `effectiveUserInterfaceLayoutDirection`

不用自己写 `if isRTL { flip }`，交给系统算。
